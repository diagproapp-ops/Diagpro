    SET data_modificacao = CURRENT_TIMESTAMP

Este gatilho, chamado update_textos_referencia_modificacao, é executado automaticamente após qualquer UPDATEoperação na sua TextosReferenciaGeraltabela.

O problema é que dentro desse gatilho, o comando SQL que ele tenta executar é:
UPDATE TextosReferenciaGeral SET data_modificacao = CURRENT_TIMESTAMP WHERE id_texto_ref_geral = OLD.id_texto_ref_geral;

Ele está tentando usar uma coluna chamada id_texto_ref_geral, que não existe na sua TextosReferenciaGeraltabela. Sua tabela usa corretamente id_texto_refcomo chave primária.

Então, quando seu código Python executa sua INSERT ... ON CONFLICT DO UPDATE ...instrução com sucesso, se isso resulta em um UPDATEem uma linha existente em TextosReferenciaGeral:

O SQL do seu código Python (que está correto e usa id_texto_ref) termina.
Este AFTER UPDATEgatilho então dispara.
O próprio gatilho tenta executar sua própria UPDATEinstrução interna, que contém o nome de coluna incorreto id_texto_ref_geral.
É aqui que o sqlite3.OperationalError: no such column: id_texto_ref_geralerro se origina – no gatilho, não mais diretamente no SQL do seu código Python.
Como corrigir isso:

Você precisa modificar este gatilho para usar o nome de coluna correto, id_texto_ref.

O gatilho corrigido deve ser:

SQL

CREATE TRIGGER update_textos_referencia_modificacao_corrigido  -- Giving it a slightly new name for clarity during recreation
AFTER UPDATE ON TextosReferenciaGeral
FOR EACH ROW
BEGIN
    UPDATE TextosReferenciaGeral 
    SET data_modificacao = CURRENT_TIMESTAMP 
    WHERE id_texto_ref = OLD.id_texto_ref; -- Corrected column name here
END;


CREATE TRIGGER update_textos_referencia_modificacao

    SET data_modificacao = CURRENT_TIMESTAMP 
    WHERE id_texto_ref_geral = OLD.id_texto_ref_geral; -- <<<< THIS IS THE PROBLEM!
END;

Opção A (Manter e Corrigir o Gatilho): Siga os passos acima para corrigir o gatilho. Isso é mais seguro se o gatilho servir para outros fins.
Opção B (Remover gatilho se redundante): Se o único motivo para esse gatilho for uma atualização data_modificacaoe seu código Python já manipula isso para todas as atualizações relevantes desta tabela, você pode simplesmente remover o gatilho e não recriá-lo.
Para consistência futura, é uma boa prática definir seus gatilhos dentro do seu core/database_setup.pyscript, assim como suas CREATE TABLEinstruções. Isso garante que, se o banco de dados for recriado, os gatilhos também sejam recriados corretamente.
